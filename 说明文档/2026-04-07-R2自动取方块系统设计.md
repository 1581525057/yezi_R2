# R2 自动取方块系统设计文档

**日期：** 2026-04-07
**项目：** ROBOCON 梅林区自动取方块任务
**车型：** R2（梅林区运行）

---

## 一、系统概述

R2 车在梅林区自主导航，依次取出目标方块。小电脑（工控机）作为决策层，通过串口 UART 与单片机（执行层）通信。整体流程分为两段：**全场导航阶段**（雷达全场坐标定位，导航至梅林附近）和**梅林执行阶段**（到达梅林第一排附近后激光重定位，执行预设路径规划）。

---

## 二、硬件配置说明

| 传感器 / 机构 | 位置 | 用途 |
|---|---|---|
| 雷达 | 车顶 | 双模式：① 全场 xy 坐标（全局定位）② 梅林局部坐标（进入梅林后使用） |
| 左侧 DT35 激光测距仪 | 车身左侧 | 获取车左侧距离（用于精定位横向校正），数据由**单片机**读取 |
| 右侧 DT35 激光测距仪 | 车身右侧 | 获取车右侧距离（用于精定位横向校正），数据由**单片机**读取 |
| 前方 DT35 激光测距仪 | 车身正前方 | 获取车距前方梅林第一排台阶的距离（用于精定位纵向校正），数据由**单片机**读取 |
| 链式爬台阶机构 | 车身主体 | 两侧链条由电机驱动，撑起整个车身实现上下台阶；车前端有小轮辅助行进 |
| 机械臂（吸取） | 车身前方 | 无云台，靠底盘整体旋转对准目标方块位置，机械臂负责吸取 |
| 底盘角度反馈（编码器或 IMU，至少其一） | 底盘 | 用于底盘旋转闭环与 `yaw` 维护；**若无该反馈，本方案不能保证旋转对准和姿态重置精度** |
| 吸附成功检测传感器（真空开关/负压传感器/等效反馈） | 机械臂 | 用于判定吸盘是否真实吸住方块；**若无该反馈，吸取 ACK 只能表示动作完成，不能表示取物成功** |

## 三、梅林结构说明

梅林共 12 个，排列为 4 排 × 3 列（第一排在最靠近我方出发区一侧）。

**第一排台阶高度（关键参数）：**

| 第一排位置 | 台阶高度 |
|---|---|
| 中间（第2个） | 20 cm |
| 左侧（第1个） | 40 cm |
| 右侧（第3个） | 40 cm |

第二排、第三排、第四排高度随机，不影响路径规划逻辑（路径由小电脑预设，执行前已确定）。

> **重要：** 由于第一排必须经过（无论目标方块在哪一排），车一定会执行上台阶动作。上哪个台阶（左/中/右）由小电脑根据预设路径告知单片机。

## 四、系统架构

```
┌─────────────────────────────────────────────────┐
│                   小电脑（工控机）                  │
│                                                  │
│  ┌──────────┐    ┌──────────────┐    ┌────────┐  │
│  │  雷达定位  │───▶│  状态机引擎   │───▶│ 串口发送│  │
│  │(全场/梅林) │    │ (决策主程序)  │    │ 模块   │  │
│  └──────────┘    └──────────────┘    └────┬───┘  │
│        ▲          ▲                       │      │
│  预设点标准值    预设路径表                  │      │
│  (赛前标定的    (赛前生成好的梅林坐标序列)   │      │
│  各点激光标准距)                            │      │
└───────────────────────────────────────────┼──────┘
                            ┌───────────────┘ UART
                            │   ▲ 到位信号（单片机精定位完成后上报）
                            ▼   │
                   ┌──────────────────┐
                   │   单片机(STM32)   │
                   │   执行层 + 感知层  │
                   │  · DT35三向激光读取│  ◀── 左/右/前 DT35
                   │  · 精定位控制逻辑  │
                   │  · 链式爬台阶     │
                   │  · 底盘驱动       │
                   │  · 机械臂吸取     │
                   └──────────────────┘
```

### 三层职责划分

| 层级 | 硬件 | 职责 |
|------|------|------|
| 感知层（粗） | 雷达 | 输出全场 xy 坐标，用于导航和粗定位 |
| 感知层（精） | 单片机 + DT35 三向激光 | 单片机直接读取左/右/前三路 DT35 数据，执行精定位闭环控制 |
| 决策层 | 小电脑状态机 | 判断当前位置 → 决定执行哪个动作 → 发串口指令给单片机；接收单片机到位信号后用预设点标准值触发雷达重新校准 |
| 执行层 | 单片机 | 收指令 → 执行精定位 → 执行动作（爬台阶/旋转底盘/机械臂吸取）→ 回 ACK |

### 姿态与坐标定义

- 本文统一使用机器人位姿 `Pose = (x, y, yaw)` 表示车辆状态，而不是只使用 `(x, y)`。
- **全场坐标系：** `Pose_global = (x_g, y_g, yaw_g)`，用于阶段一导航。
- **梅林局部坐标系：** `Pose_local = (x_l, y_l, yaw_l)`，用于阶段二动作触发与执行。
- 若雷达仅提供 `(x, y)`，则 `yaw` 必须由底盘角度反馈闭环维护；**任何“重校准”都必须明确是否同时重置 `yaw`。本文后续统一规定：重校准为将当前位姿强制对齐到预设位姿 `(x_i, y_i, yaw_i)`。**
- 所有预设点必须同时保存：
  - 预设位姿：`(x_i, y_i, yaw_i)`
  - DT35 标准值：`(L_ref, R_ref, F_ref)`
  - 容差参数：`tol_x, tol_y, tol_yaw`
  - 执行超时：`timeout_ms`

## 五、整体流程概述

整个任务分为**两个大阶段**，以"到达梅林第一排附近"为分界点：

```
[阶段一：全场导航]  →  [分界点：到达梅林第一排附近]  →  [阶段二：梅林路径执行]
```

---

## 六、阶段一：全场导航至梅林附近

### 6.1 目标

将车从出发区导航至梅林第一排正前方附近，使车进入可以启动激光重定位的有效范围。

### 6.2 定位依据

- **数据来源：** 雷达的全场 xy 坐标模式
- 小电脑持续读取雷达输出的全场坐标 (x, y)
- 对比预设的"梅林触发坐标"（赛前标定好的，代表车到达梅林第一排附近时的全场坐标）
- 当雷达坐标进入触发范围内，判定车已到达梅林附近，进入阶段二

### 6.3 导航方式

- 小电脑根据雷达全场坐标，持续给单片机发送移动指令（前进、转向）
- 单片机每完成一条移动指令后回 ACK，小电脑再发下一条
- 导航路径为赛前规划好的固定路线，不做实时重规划
- 本方案采用**离散动作导航**而非连续速度流控制：小电脑下发的是“移动到下一个离散触发点所需的动作片段”，例如 `前进 30 cm`、`左转 15°`。若后续改为连续速度闭环，需单独重写通信与安全策略。

### 6.4 阶段一结束条件

雷达全场坐标显示车已进入梅林第一排附近的预设触发区域。

## 七、分界点：两级定位（粗定位 + 精定位）

### 7.1 定位架构概述

到达梅林第一排附近后，执行两级定位：

| 级别 | 传感器 | 执行方 | 说明 |
|------|--------|--------|------|
| 粗定位 | 雷达 | 小电脑 | 导航至梅林第一排附近预设触发区域 |
| 精定位 | DT35 三向激光 | **单片机** | 单片机读取 DT35 数据，闭环控制底盘微调至精确位置 |

### 7.2 为什么需要两级定位

雷达在全场移动过程中可能发生累积漂移，坐标精度不足以直接执行梅林内的精细动作。精定位由单片机直接读取 DT35 激光数据并闭环控制，响应速度更快，精度更高。

### 7.3 精定位执行流程（单片机侧）

小电脑发送「执行精定位」指令后，单片机自主完成以下闭环：

| DT35 激光 | 测量内容 | 校正作用 |
|---|---|---|
| 左侧 DT35 | 车左侧到左侧边界（或梅林侧面）的距离 | 校正车的横向偏移（左右位置） |
| 右侧 DT35 | 车右侧到右侧边界的距离 | 与左侧联合校正横向位置，并校正车身是否歪斜 |
| 前方 DT35 | 车正前方到梅林第一排台阶的距离 | 校正车的纵向位置（与第一排台阶的距离） |

精定位闭环步骤（单片机内部）：

1. 读取左/右/前三路 DT35 当前测距值
2. 与小电脑发送过来的**该预设点标准距离值** `(L_ref, R_ref, F_ref)` 进行对比
3. 计算偏差：
   - `e_L = L_meas - L_ref`
   - `e_R = R_meas - R_ref`
   - `e_F = F_meas - F_ref`
   - **横向偏差观测量：** `e_lat = (e_L - e_R) / 2`
   - **角度偏差观测量：** `e_yaw_obs = (L_meas - R_meas) - (L_ref - R_ref)`
   - **纵向偏差：** `e_lon = e_F`
   - 说明：以上定义**不假设目标点左右等距**，避免直接使用 `(左 - 右) / 2` 带来的隐含对称假设
4. 单片机按固定次序执行微调：
   - 先消除 `e_yaw_obs`
   - 再消除 `e_lat`
   - 最后消除 `e_lon`
   - 若底盘支持多环解耦控制，也可并行收敛，但判定标准必须仍按 `tol_yaw / tol_x / tol_y`
5. 每次微调后重新读取三路 DT35，验证偏差是否进入容差范围
6. 若连续 `N_stable` 次测量均满足容差，则判定精定位完成
7. 若超过 `timeout_ms` 或 `max_retry` 仍未达标，则返回失败 ACK，不得无限闭环
8. 精度达标后，单片机**上报到位信号（DONE ACK）给小电脑**

### 7.4 小电脑收到到位信号后的动作

1. 收到单片机的到位 ACK
2. 由于该点位是**预设好的固定点**，小电脑以该预设点的标准位姿 `(x_i, y_i, yaw_i)` **重新校准当前位姿**：
   - 若雷达支持位姿重置：将雷达当前输出强制对齐到 `(x_i, y_i, yaw_i)`
   - 若雷达仅支持坐标重置：至少重置 `(x_i, y_i)`，并同步将底盘角度反馈零点或参考角对齐到 `yaw_i`
   - 若系统无法重置 `yaw`，则该点**不得**作为后续旋转取物动作的高精度基准点
3. 雷达坐标重置完成，进入阶段二

### 7.5 上台阶后重新定位

**每次上完台阶后，必须重新执行一次两级定位：**

```
[上台阶完成，单片机回 DONE ACK]
        │
        ▼
[小电脑发送「执行精定位」指令，携带该台阶顶部预设点的标准距离值]
        │
        ▼
[单片机读取 DT35，闭环微调至精确位置]
        │
        ▼
[单片机上报到位 DONE ACK]
        │
        ▼
[小电脑用该预设点标准位姿重新校准当前位姿]
        │
        ▼
[继续执行后续梅林路径动作]
```

原因：上台阶过程中车身有抖动和位移，累积误差较大，必须重新校准才能保证后续动作精度。

## 八、阶段二：梅林路径规划执行

### 8.1 路径的预生成方式

- **赛前生成：** 梅林的所有台阶坐标（基于梅林局部坐标系）在赛前已测量完毕，小电脑存储了完整的行动序列表
- **行动序列结构：** 每一条记录 = 触发坐标 + 对应动作指令
  - 例：到达坐标 (-2, 2) → 发送"上台阶"指令给单片机
  - 例：到达坐标 (-2, 4) → 发送"旋转底盘 90°"指令给单片机
  - 例：到达坐标 (-2, 4.5) → 发送"机械臂吸取"指令给单片机
- **比赛时目标输入：** 对方将方块放置完毕后，操作人员立即将目标方块所在位置编号输入小电脑，小电脑从预设序列中提取对应的完整行动路径，开赛信号一到立即执行

### 8.2 坐标系切换

- 进入阶段二后，小电脑从"雷达全场坐标"切换为"雷达梅林局部坐标"
- 梅林局部坐标系以梅林第一排某固定点为原点，仅包含梅林区域内的位置数据
- 激光重定位完成后建立起准确的局部坐标基准
- 阶段二中所有触发点默认使用 `Pose_local = (x_l, y_l, yaw_l)` 进行判定；其中：
  - 纯移动触发至少校验 `x/y`
  - 旋转、吸取、下台阶等姿态敏感动作必须同时校验 `yaw`

### 8.3 阶段二执行循环

```
[读取当前雷达梅林坐标]
        │
        ▼
[对比行动序列表，查找匹配的触发坐标]
        │
        ├── 未到达触发点 → 继续导航移动（发移动指令给单片机）
        │
        └── 到达触发点（`|x-x_i|<=tol_x` 且 `|y-y_i|<=tol_y`；如该动作需要姿态约束，则还需 `|yaw-yaw_i|<=tol_yaw`）
                │
                ▼
        [发送对应动作指令给单片机]
                │
                ├── 若动作为「上台阶」：
                │       单片机执行上台阶 → 回 DONE ACK
                │       小电脑发「精定位」指令（携带台阶顶预设点标准值）
                │       单片机 DT35 闭环精定位 → 回 DONE ACK
                │       小电脑用预设点标准位姿重新校准当前位姿
                │       继续下一步
                │
                ├── 若动作为其他（旋转/吸取/移动）：
                │       单片机执行动作 → 回 DONE ACK
                │
                ├── DONE ACK：成功 → 从行动序列表取下一条，继续循环
                │
                └── DONE ACK：失败 → 按失败处理策略处理（见下文）
```

### 8.4 具体动作类型说明

#### 动作一：上台阶

- **触发时机：** 小电脑判定车到达某个台阶入口坐标
- **机构原理：** 链式结构，两侧链条由电机驱动运转，撑起整个车身；车前端小轮在地面行进配合链条完成爬升
- **小电脑告知单片机内容：** 上哪个台阶（左/中/右，对应高度 40/20/40 cm）
- **完成判定：** 单片机执行完爬台阶动作并满足机构到位条件后回 DONE ACK

#### 动作二：底盘旋转对准

- **触发时机：** 到达取方块位置坐标后，机械臂需要对准方块
- **机构原理：** 机械臂无云台，无法独立转动，必须靠整个底盘旋转特定角度将机械臂指向目标方块
- **小电脑告知单片机内容：** 旋转角度（°）和旋转方向
- **完成判定：** 单片机执行完旋转后，需满足 `|yaw_actual - yaw_target| <= tol_yaw` 且连续稳定 `N_stable` 个采样周期后回 DONE ACK

#### 动作三：机械臂吸取方块

- **触发时机：** 底盘旋转到位后，机械臂正对目标方块
- **机构原理：** 机械臂伸出并启动吸盘，吸取方块
- **小电脑告知单片机内容：** 执行吸取动作
- **完成判定：**
  - 若存在真空开关/负压传感器/等效检测：以传感器结果返回 DONE ACK（成功 / 失败）
  - 若不存在吸附检测传感器：协议中必须明确返回 `动作执行完成但取物结果未知`，不得伪报“吸取成功”

#### 动作四：下台阶

- **触发时机：** 方块吸取成功后，需要下台阶回到通道
- **机构原理：** 与上台阶反向，链式机构反转下降
- **完成判定：** 单片机执行完下台阶动作并满足机构到位条件后回 DONE ACK

#### 动作五：底盘平移 / 前进 / 转向

- **用途：** 在梅林内移动至各坐标点之间的常规移动
- **小电脑告知单片机内容：** 移动方向、距离或角度
- **完成判定：** 单片机执行完运动并满足位置误差容差后回 DONE ACK

### 8.5 失败处理策略

| 失败类型 | 处理方式 |
|---|---|
| 吸取失败（DONE ACK 返回失败） | 退回该台阶入口，重试一次；重试仍失败则跳过该目标，处理下一个 |
| 单片机超时未回 ACK | 先区分 `RECV_ACK` 超时还是 `DONE_ACK` 超时；前者按通信错误处理，后者按动作执行超时处理 |
| 坐标偏差超出允许范围 | 原地微调到位后重新触发当前步骤 |
| 精定位超时 / DT35 连续异常 | 本次精定位直接判定失败，车辆退回上一安全点；若连续失败超过阈值则停车报警 |
| 上台阶失败 / 卡阶 | 立即停止链条与底盘动作，维持抱闸或安全姿态，回 FAIL ACK，并禁止自动重试超过一次 |
| 雷达局部坐标丢失或重校准失败 | 退出阶段二，回到人工接管或安全停车状态，不得继续盲走 |
| 底盘旋转完成但姿态误差超限 | 重新执行一次角度闭环；再次失败则放弃当前取物动作 |

## 九、通信协议设计原则

### 小电脑 → 单片机（指令帧）

每条指令包含：
- 固定帧头 `SOF = 0xAA55`
- 协议版本 `ver`
- 序号 `seq`
- 指令类型（前进 / 转向 / 上台阶 / 下台阶 / 底盘旋转 / 机械臂吸取 / **精定位** / 停止）
- 参数区 `payload`
  - 普通移动：距离 `cm`、角度 `deg`、速度档位
  - 上下台阶：目标台阶编号、动作超时
  - 精定位：`preset_id`、`L_ref`、`R_ref`、`F_ref`、`tol_x`、`tol_y`、`tol_yaw`、`timeout_ms`
- 负载长度 `payload_len`
- `CRC16` 校验

### 单片机 → 小电脑（ACK 帧）

每条 ACK 包含：
- 固定帧头 `SOF = 0x55AA`
- 协议版本 `ver`
- 对应序号 `seq`
- 对应指令类型 `cmd`
- ACK 类型：
  - `RECV_ACK`：表示已收帧且校验通过
  - `DONE_ACK`：表示动作执行结束
- 执行结果（成功 / 失败 / 未知）
- 失败原因码（可选）
- **精定位完成时：附带实际测量值 `(L_meas, R_meas, F_meas)` 与最终误差（建议必带，用于调试和赛场判因）**
- `CRC16` 校验

### 失败原因码最小集合

- `0x01`：CRC 错误
- `0x02`：未知指令
- `0x03`：参数非法
- `0x04`：执行超时
- `0x05`：DT35 数据无效
- `0x06`：台阶动作失败
- `0x07`：吸附失败
- `0x08`：姿态误差超限
- `0x09`：安全停机触发

### 核心规则

| 规则 | 说明 |
|------|------|
| 每条指令两级确认 | 发送后先等 `RECV_ACK`（确认收帧），再等 `DONE_ACK`（确认执行结束） |
| 每步等 DONE ACK | 小电脑在收到当前动作的 `DONE_ACK` 前不得发送下一条动作指令 |
| 超时重发 | `RECV_ACK` 超时按通信错误处理；`DONE_ACK` 超时按执行超时处理，二者不可混为一类 |
| 指令去重 | 单片机必须按 `seq` 去重，避免上位机重发造成重复执行 |
| 顺序执行 | 所有指令严格串行，无并发 |

## 十、关键设计原则汇总

| 原则 | 说明 |
|------|------|
| 两段式定位 | 全场导航用雷达全场坐标；梅林执行用雷达梅林坐标 + DT35 精定位 |
| 两级定位架构 | 雷达粗定位（小电脑侧）+ DT35 精定位（单片机侧闭环），分工明确 |
| 单片机读 DT35 | 三向 DT35 激光数据直接由单片机读取并处理，精定位闭环在单片机内完成 |
| 到位后校准位姿 | 单片机精定位完成上报信号后，小电脑用该预设点标准位姿重新校准当前 `(x, y, yaw)`，消除漂移 |
| 上台阶后必重定位 | 每次上完台阶，必须重新执行精定位 + 雷达重校准，保证后续精度 |
| 路径赛前预生成 | 梅林内所有坐标触发点和对应动作在赛前全部生成好，比赛中不实时规划 |
| 底盘转而非云台 | 机械臂无云台，取方块必须靠底盘旋转对准，小电脑需精确计算旋转角度 |
| 链式上下台阶 | 爬台阶靠两侧链条+前轮，上下哪个台阶由小电脑根据路径序列告知单片机 |
| 每步等 DONE ACK | 串行通信，严格等待执行完成再发下一条 |
| 失败重试一次 | 吸取失败退回重试，超次跳过并报警 |
| 位姿全量校准 | 每次精定位成功后，必须明确校准 `(x, y, yaw)`，不能只校准 `(x, y)` 而忽略朝向 |
| 成功定义可观测 | “动作成功”必须对应可观测的完成条件；吸取成功必须由传感器闭环支撑 |

## 十一、状态转移总览

```
[初始化 & 待命]
    │ 赛前：测量梅林坐标，预生成行动序列；标定各预设点 DT35 标准距离值
    │ 临赛：输入目标方块位置 → 小电脑提取对应路径
    │ 开始信号
    ▼
[阶段一：全场导航]
    │ 雷达全场坐标持续比对
    │ 到达梅林触发区域（粗定位）
    ▼
[精定位：小电脑发指令 → 单片机读 DT35 闭环微调]
    │ 单片机精定位完成，上报到位信号
    ▼
[小电脑用预设点标准位姿重新校准当前位姿]
    │ 雷达坐标重置完成
    ▼
[阶段二：梅林路径执行] ◀──────────────────────────────┐
    │ 读取雷达梅林坐标                                  │
    │ 比对行动序列表                                    │
    ├── 未到触发点 → 发移动指令 → 等 DONE ACK → 继续    │
    └── 到达触发点 → 发动作指令 → 等 DONE ACK           │
          │                                            │
          ├── 普通动作（旋转/吸取）→ DONE ACK → 继续 ─▶┘
          │
          └── 上台阶动作 → DONE ACK
                    │
                    ▼
          [精定位：单片机 DT35 闭环 → DONE ACK]
                    │
                    ▼
[小电脑重新校准当前位姿] ──────────────────▶┘
                    │ 全部行动完成
                    ▼
             [任务完成 / 停车]
```

## 十二、技术评审结论与必须闭合项

以下事项在进入联调前必须闭合，否则本方案仍存在较高落地风险。

### P0（未闭合则不得进入正式联调）

1. **姿态来源闭合**
   - 必须明确 `yaw` 的真实来源：雷达、编码器、IMU 或其组合。
   - 若无法稳定获得 `yaw`，则“底盘旋转对准方块”与“位姿重校准”均不成立。

2. **吸取成功判定闭合**
   - 必须明确是否具备吸附成功传感器。
   - 若无该传感器，协议和状态机中不得使用“吸取成功”作为可靠条件。

3. **串口协议冻结**
   - 必须输出正式协议表：字段长度、字节序、`CRC16` 方案、超时值、错误码、重发规则。
   - 小电脑与 STM32 必须使用同一份冻结版协议，不允许“口头约定”。

4. **精定位参数表冻结**
   - 必须为每个预设点冻结 `(x_i, y_i, yaw_i)`、`(L_ref, R_ref, F_ref)`、容差和超时。
   - 若赛前只测了坐标、未测 `yaw` 和三路 DT35 标准值，则精定位无法闭环验收。

### P1（建议在赛前全流程演练前闭合）

1. **动作超时表**
   - 为前进、转向、旋转、上台阶、下台阶、吸取、精定位分别定义默认超时与最大允许时长。

2. **安全点与回退策略**
   - 明确“上一安全点”集合，避免失败后退回到不可达或更危险的位置。

3. **赛场调试日志**
   - 小电脑必须保存 `seq / cmd / ack / pose / DT35` 的关键日志，便于赛场快速判因。

### 当前评审结论

- 该方案的总体架构合理，可以继续推进。
- 但在 `yaw` 来源、吸取成功判定、协议冻结、精定位参数冻结四项 P0 问题闭合前，**不建议直接进入双端编码与联调阶段**。
