# 删除旧版 KFS 放置流程设计

## 目标

完整删除旧版 `CONBAT_PLACE_KFS` 流程，保留并继续使用新版
`CONBAT_PLACE_KFS_NEW` 流程，不改变其他战斗任务和路线任务行为。

## 修改范围

- 从 `ConbatState` 删除旧版 `CONBAT_PLACE_KFS` 状态。
- 从 `CONBAT_TASK::runOnce()` 删除旧版状态分支。
- 删除 `runPlaceKfs()` 的声明和实现。
- 删除旧版 `PlaceKfsStep` 子状态、旧版专用成员及对应复位代码。
- 删除仅由旧版实现使用的参数。
- 保留新版使用的停止判定、路径选择、放置后等待等公共逻辑。
- 将新版仍使用的前进速度参数更名为新版专用名称，消除旧版命名残留。

## 兼容性判断

全仓搜索未发现 `ConbatState` 的数值被通信协议、持久化数据或数组索引使用。
删除旧状态会使其后枚举值前移，但当前代码只按枚举符号比较，因此无需保留占位值。

## 验证

1. 全仓搜索旧状态、旧函数、旧子状态和旧版专用成员，结果应为空。
2. 搜索新版流程依赖，确认其入口和公共放置逻辑仍完整。
3. 执行项目现有构建；若环境无法完整构建，则至少运行可用的编译或静态检查并报告限制。
4. 检查 Git 差异，确保不改动已有的 `route_task.cpp`、`route_task.h` 工作区修改。
